# 1.0.11 — 白板刷新、布局与 PDF 生命周期优化

## 本轮变更

1. 相机刷新跳过空编辑目标的全板查找，仅检查已挂载 DOM 的标题编辑器，同帧复用查询；离屏编辑仍保留，按原白板顺序绘制。
2. 分支索引按需计算；稳定视口复用卡片时不再重复构建父子拓扑，折叠可见性、新节点入窗和详情级别变化仍使用当前状态。
3. 整理布局的预览和应用各自在同步调用内复用折叠移动单元；不保留跨操作缓存。隐藏节点、锁定、分组包含、预览过期及旧版无签名计划的提前拒绝保持不变。
4. PDF 缩略图的加载、读文档、读页及渲染阶段都可取消；总等待预算 15 秒。取消或超时及时释放队列，工作线程销毁不再阻塞下一张预览；失败/取消画布的 backing storage 立即释放。
5. PDF 超时任务退出缓存，立即重试可创建新任务；其他卡片持有的旧文档继续可用，最后一个引用释放后才销毁。池关闭覆盖多代退役任务，迟到失败不能删除新缓存。
6. PDF 线程同步销毁异常不会中断其余清理；普通笔记搜索/关联弹窗关闭异常也不再遗留其他弹窗、帧、选区全文、工具栏监听和界面。
7. Markdown 工具栏仅在值变化时更新关联笔记按钮的 disabled/title 属性，保持实时格式扫描和选区检查。

## 验证结果

- 完整测试 **2,321/2,321** 通过，本轮新增 38 项；发布校验 **7/7** 通过。
- TypeScript、生产构建、差异空白检查通过；ESLint **0 错误，79 项既有警告**。
- 定向回归先在原实现执行，确认重复遍历、取消阻塞和清理中断，再验证修复；PDF 立即重试的补充审阅发现已修复并加入共享卡存活回归。
- 700 个预览及 700 个布局应用差分一致，覆盖全部 16 种布局、隐藏分支、锁定、分组、关联边、过期预览；4 类旧计划早拒绝仍不读取边。
- 原生 Obsidian 使用 1,200 节点白板对比 1.0.10 / 1.0.11，各执行 120 次相机刷新；16 项编辑/折叠检查两版均通过。
- 另有 11 项原生 PDF 验证通过：以受控未完成 Promise 占满真实双槽队列后折叠卡片，后续原生 PDF.js 预览正常完成；独立页画布、有限像素尺寸、页数、翻页、保存和撤销重做均通过。
