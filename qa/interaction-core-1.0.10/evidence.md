# 1.0.10 — 白板与编辑交互底层优化

## 本轮实施

1. 普通笔记工具栏只读快照复用同一 CodeMirror 不可变文档的字符串；编辑、撤销、阅读器函数、编辑器/文档身份变化及卸载均使缓存失效。实际格式化、聚焦和文件保存的实时冲突校验不走缓存。
2. 框选先判断矩形是否可能命中对象；空白或零面积无需扫描父子关系。实际命中时仍使用当前折叠状态和分组显示尺寸，不缓存可变白板。
3. 重接连线保留可验证的数组位置，逐帧重取当前边。重排、同 ID 替换、删除及数组替换仍实时；提交时保留原有冲突检查。
4. 长文本连接提示先截取 24 字符再拆分首行，保持相同输出，减少鼠标移动期间的整段文本处理。
5. 分组移动检查在一次操作内共用已有节点/空间索引，保留原来的逐根顺序、提前拒绝及锁定检查。下一次操作重新建索引。
6. 文本预览挂载后交给 Obsidian 原生渲染，并保留实际根节点的样式、方向和事件。失败恢复原文，取消隔离迟到结果；原生清理前移出白板所属的引用按钮，完成后归位。

## 验证

- 完整测试 2,283 项通过，比 1.0.9 新增 33 项；7 项发布验证通过。
- 构建、TypeScript、git diff --check 通过；ESLint 0 错误，仍为原有 79 项警告。
- 新增性能/生命周期回归先在旧源码失败，再对修复通过。
- 10,000 个框选差分场景的选择集与原实现一致，覆盖混合折叠、分组及各类边；没有改变分组完全框住才选中的规则。
- 600 个分组移动差分场景的计划或错误相同；首个冲突的属性读取次数逐项一致，验证未牺牲早拒绝路径。
- 独立复核覆盖 CM 同长度编辑、撤销重做、IME、多光标、窗口/读取器替换，连线索引失配和预览取消/公式/图片/引用生命周期。

## Obsidian 原生验证

临时 1,003 节点白板完成 22 项检查：可见/空白框选、折叠隐藏排除、逐层展开、同 ID 连线样式更新、重排后重接、原生编辑、Markdown 格式化、相机刷新保留草稿、保存、撤销重做及测量表面清理。

通过 Obsidian 官方注册接口安装临时后处理器，限定临时测试白板：1.0.9 收到未挂载的文本根且根部标记丢失；1.0.10 所有目标均已挂载，3 个当前文本根保留标记，2 个公式及 1 个表格正常渲染，队列排空。测试钩子在 finally 内注销。

原生笔记 120 次选区更新实际读数为 120 → 1，所有文本和选区一致。检查期间 document.hidden=false，但没有测整机 FPS 或宣称全应用无泄漏。

## 未采用的方案

大纲空间索引在平铺白板更快，但深层嵌套显著退化，因此未实施。合并所有折叠根一次展开会损害首个冲突的早拒绝，改为在原遍历顺序内共享索引。
