# ThoughtSpace 编辑气质 UI 设计规范

- 日期：2026-11-11
- 状态：待审阅
- 适用版本：1.3.50 之后的打磨工作
- 气质：安静的纸面编辑感——暖白纸、克制动效、排版清楚，像一本做得很精的笔记本
- 品质目标：按 Awwwards、Webby Awards、FWA 的工艺标准来打磨全部插件界面，并通过自我检查反复提升，直到达标。这里的「获奖级」指的是一本做得很精的笔记本，而不是花哨的展示站。ThoughtSpace 是 Obsidian 插件，窗口外壳和系统主题仍由宿主提供；打磨范围是插件内全部可及的界面。

本文档是后续实施的唯一依据。换布局、改组件、做验收，都以本文为准。

## 1. 原则

- 全插件共用同一套视觉语言：工具面板、整理白板、写作预览、卡片库、白板、导出和设置都像同一本笔记本里的页面。
- 浅色默认底是暖白纸 `#f8f5ef`，通用背景和描边排除黄、金色倾向（包括旧黄 `#f3e9d4` 及同类奶油色、金色边）。
- 标题、正文、辅助信息有稳定的字号、字重和行高层次。
- 间距使用同一套尺度，不挤也不散。
- 纸的纹理继续内联在 `styles.css` 中，只作用于背景层；阴影和装饰描边都很轻。
- 动效短，只用来交代打开、折叠或切换，不弹、不炫。
- 不改现有功能，只把结构和视觉收顺。用户已经指定的卡片颜色予以保留。
- Obsidian 的窗口外壳、现有能力、日历隔离、最低版本和白板格式兼容性都不变。

## 2. 设计系统

设计系统由用途明确的颜色、主题层次、对比度底线、字体与间距用法、布局与密度、纹理与动效限度，以及「基础数值 → 用途变量 → 组件样式」三层结构组成。只列数值不够，必须同时写清用在哪里。

### 2.1 颜色按用途定义，卡片色与状态色分开

除三档墨色外，浅色与深色都要明确三种表面：

| 用途 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| 页面底 | `#f8f5ef`（锁定的默认值） | 低饱和中性深灰，作为最底一层 |
| 面板底 | 与页面同色相，仅用极小的明度差区分；可以与页面底相同，靠留白、分隔线或发丝边区分 | 比页面底略亮的中性深灰 |
| 浮层底 | 比面板再亮半级，配合发丝边与很轻的阴影 | 比面板再亮一级，同样用边与轻阴影抬起 |

浅色的面板和浮层不得向旧黄 `#f3e9d4` 或金色偏移。深色表面保持接近无彩的中性深灰，不用偏黄的暖棕。

三档墨色：

- 标题：最深，用于界面标题、文章标题、分组名称。
- 正文：稍软，用于可读的主要内容。
- 辅助信息：更淡，但必须仍然易读，不得直接套用禁用态的淡色。

描边分为两档：

- 装饰描边：浅暖灰，可以很淡，只用来轻轻分开区域。
- 操作描边：用于输入框边界、键盘焦点、选中标记，必须有足够辨识度。

既定卡片颜色保留。选中用轮廓、勾选或局部标记表达，避免覆盖卡片原色。选中与「正确 / 成功」必须使用不同的表达方式，防止含义混淆。对错同时提供文字或图标，不只靠颜色。

除页面底 `#f8f5ef` 已锁定外，其余具体色值在实施时按本章对比度规则计算，并写入用途变量；不得凭感觉临时写进某个界面。

### 2.2 深浅主题统一层次，各自确定色值

- 深浅主题使用同一套表面层次和文字角色，但各自确定色值，互不混用。
- 深色通过表面亮度区分页面、面板和浮层；文字、边框和卡片色分别适配。
- 卡片在深色主题中保留颜色辨识度，但允许调整亮度和饱和度，不改色相到无法辨认。
- 主题切换跟随 Obsidian 当前模式。插件通过 CSS 变量与宿主主题协调，见 [Obsidian 样式文档](https://docs.obsidian.md/Reference/CSS%20variables/About%20styling)。
- 字体、字号缩放和强调色等可跟随宿主变量；表面、墨色、描边和组件状态以本插件用途变量为准，并限定在插件容器内。

### 2.3 「轻」的例外：操作线索必须清楚

装饰可以很淡，但下面这些线索必须清楚：

- 输入框边界
- 键盘焦点
- 选中标记
- 可点击控件的可辨识外形

可读性底线：

- 普通文字（标题、正文、辅助信息）对比度至少 4.5∶1，见 [WCAG 2.2 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- 识别控件和状态所必需的视觉线索至少 3∶1，见 [WCAG 2.2 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。
- 对错等状态同时提供文字或图标。
- 禁用态可以更淡，但不得用于仍然需要阅读的辅助文字。

### 2.4 字号和间距：既有数值，也有用途

- 字体继承 Obsidian，不另引花哨字体。
- 字号基于宿主尺度（如 `--font-text-size`），并支持用户缩放。绝对像素只作为默认换算参考，实现时用相对单位。
- 间距数值以默认像素计，实现时换算为相对单位，随界面缩放保持比例。

文字角色（相对宿主正文字号）：

| 角色 | 字号 | 字重 | 行高 | 用在哪里 |
| --- | --- | --- | --- | --- |
| 标题 | 1.25em | 600 | 1.3 | 界面标题、文章标题、需要首先被看见的名称 |
| 正文 | 1em | 400 | 1.55 | 工具说明、列表主文案、设置说明、写作正文 |
| 辅助信息 | 0.8125em | 400 | 1.4 | 元信息、分组标签、次要提示；对比度仍须 ≥ 4.5∶1 |

间距：

| 用途 | 尺度 |
| --- | --- |
| 图标与文字 | 4–8 |
| 控件之间 | 8–12 |
| 面板内距 | 默认 16 |
| 区块之间 | 24–32 |

圆角只使用 4、8、12 三档：小控件与输入框用 4，按钮与卡片用 8，大型面板或弹窗可用 12。

### 2.5 布局与密度

- 窄侧栏、宽面板和弹窗使用同一套尺度，但允许不同密度：侧栏更紧，阅读区和预览区更松。
- 布局依据插件所在容器的宽度调整，而不是整个操作系统窗口；须覆盖侧栏、分屏和弹窗。
- 空间不足时，优先换行、重排和收纳次要操作，而不是缩小到难以点击或难以阅读。
- 长标题截断、正文换行、工具栏溢出和滚动区域必须统一处理，避免各界面临时发明规则。

### 2.6 纹理与动效的限度

- 纸纹继续以内联 PNG data URI 的形式放在 `styles.css` 中（社区更新器只发布 `main.js`、`manifest.json`、`styles.css`），不得拆成单独文件。
- 纸纹只作用于背景层，避免多层嵌套叠加。
- 深色主题降低纹理强度。
- 普通列表以留白和分隔线组织，阴影主要用于浮层。
- 打开、折叠、切换采用约 200ms、ease-in-out、无回弹。
- 响应系统「减少动态效果」设置，关闭非必要运动，见 [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。

### 2.7 三层结构与组件规范

采用「基础数值 → 用途变量 → 组件样式」：

1. 基础数值：颜色原值、间距阶梯、圆角档位、动效时长。
2. 用途变量：例如页面底、面板底、浮层底、三档墨色、装饰描边、操作描边、焦点、选中、错误、成功。
3. 组件样式：按钮、输入框、列表项、卡片、弹窗只引用用途变量，不直接写散落的魔数。

所有自家插件界面从同一份源定义更新，样式限定在插件容器内（沿用现有的 `.ts-root` 或既有插件根作用域，并保持日历隔离守卫）。

组件必须统一这些状态：悬停、按下、键盘焦点、选中、禁用、错误；空状态与加载状态也采用共同样式。选中态不得覆盖卡片固有色；错误信息靠近对应字段，并伴随文字或图标。

## 3. 组件样板页

在落地各主界面布局之前，先做一张插件内的组件样板页，作为可见、可检查的统一标准。后续所有布局修改都对照这张样板验收。

样板页必须包含：

- 三档文字（标题、正文、辅助信息）
- 既定配色卡片，并演示选中标记与卡片色并存
- 按钮、输入框、列表（含悬停、焦点、禁用、错误、空状态、加载）
- 浅色 / 深色主题切换（跟随或模拟 Obsidian 当前模式）
- 窄容器 / 宽容器切换

样板页用命令打开，不放进日常入口，以免干扰正常使用。它必须运行在真实的插件容器里，才能按宿主主题和用户字号来验收。

## 4. 落地顺序

按分层反复打磨推进，不把全部工作一次性混在一个无结构的大改动里：

1. **收完去黄改暖白。** 清掉全部默认黄、金色倾向的背景和描边，浅色默认底落到 `#f8f5ef`。此步可先于完整变量体系完成，但不得引入新的黄色默认值。
2. **建立变量、组件规范和插件内样板页。** 完成三层结构，并用样板页验收浅色、深色、窄宽容器和各组件状态。
3. **Refining 各主界面布局，并补上克制动效。** 依据第 5 章规范调整工具、整理、写作、卡片库、白板、导出和设置，同时落实约 200ms 动效与「减少动态效果」。
4. **对照样板页多轮自查，直到达标。** 每个主界面都检查浅色、深色、窄容器、长内容和空状态；不达标就回到变量或该界面继续打磨，而不是另起一套样式。

在用户明确批准之前，不升版本、不合并、不打标签、不发布。

## 5. 各主界面布局规范

不改现有功能，只把结构收顺，并让每一页的主要任务更突出。各界面共用对齐、间距和交互规则。

### 5.1 三条边界

- **暖白纸面限定为浅色主题的默认值。** 深色主题继续使用对应的深灰层次；用户已指定的卡片色和内容背景保留。
- **长标题按场景处理。** 工具项、材料项、表格单元格可以截断，同时必须能查看完整标题：提供悬停提示，并且在键盘焦点下也能读到完整名称。写作预览中的文章标题允许自然换行，不得截成一行省略号。
- **收纳次要选项要保留入口。** 折叠后参数不重置；已生效的选项可以通过摘要或数量提示看见，避免用户忘记当前设置。

### 5.2 工具面板

- 搜索框、分类标题、列表正文共用左对齐线。
- 组内间距紧，组间留白明显。
- 分类标题以字重和间距区分，而不是靠浓重色块。
- 长列表滚动时，搜索入口保持可达。

### 5.3 整理白板

- 左栏以容纳控件为准，测定后写入最小和最大宽度变量；右栏占据剩余空间，优先保证预览可用。
- 窄容器先折叠高级参数，再调整为上下布局。
- 控件标签、说明和输入区域保持稳定顺序。
- 预览里未指定颜色的默认卡片使用当前主题的页面底和装饰描边，不得回到偏黄的默认卡片。

### 5.4 写作预览

- 正文居中，阅读宽度上限为 40rem（按宿主正文字号计算，大约 60–70 个字）；窗口变宽时增加两侧留白，而不是把行宽拉得过长。
- 工具条保留高频操作，材料库可收起。
- 材料列表用分隔线和组间留白组织，不靠阴影堆叠。
- 打开工具或材料时，尽量保持正文阅读位置。

### 5.5 卡片库

- 列表、表格、看板共用文字角色、状态标记和操作命名；密度可以随视图调整。
- 切换视图时保留搜索、筛选与选择状态。
- 选中标记始终与卡片固有色并存。

### 5.6 白板

- 画布缩放、选区、悬浮工具形成固定的控件层级，避免遮住当前编辑内容。
- 画布内容可自由缩放，工具按钮维持稳定的可操作尺寸。
- 功能轮廓清楚，装饰边框保持轻。
- 浅色主题的默认画布为暖白纸面；深色主题使用对应的页面底，并降低纸纹强度。

### 5.7 导出与设置

- 按任务分区；区块内统一标签、说明、输入框的排列。
- 主操作位置稳定。
- 错误信息靠近对应字段。
- 加载时保留必要结构；空状态提供简短说明和明确的下一步入口。

### 5.8 滚动与响应式

- 每个界面明确由哪个区域负责滚动，尽量减少多层滚动。
- 确需左右独立滚动时，让滚动范围清楚。
- 响应式变化依据插件容器宽度，覆盖侧栏、分屏和弹窗。

## 6. 验收条件

### 6.1 「不改现有功能」

以下条件全部满足，才算没有改动现有功能：

- 入口可达
- 参数保留（含收纳、折叠之后）
- 快捷键不变
- 选择状态不丢（含视图切换之后）
- 导出逻辑不变

### 6.2 对照样板页的视觉验收

每个主界面都对照组件样板，至少检查：

- 浅色主题
- 深色主题
- 窄容器
- 长内容（长标题、长列表、长正文）
- 空状态
- 如适用：加载状态、错误状态、键盘焦点、选中与卡片色并存

### 6.3 品质自查

每一轮打磨结束后，用第 1 章原则和第 2 章设计系统回看全部已改界面：层次是否清楚、间距是否同一套尺度、操作线索是否够清楚、是否重新出现黄或金色默认值、动效是否过当。未达标则继续打磨，直到达到本文的品质标准。

## 7. 明确不做

- 不提供托管分享链接、插件内模型、独立绘图层或单独的手机应用。
- 不把白板格式升到需要破坏兼容的版本；保持现有 v3 兼容。
- 不提高最低 Obsidian 版本（当前为 1.13.7）。
- 不把纸纹拆成独立资源文件。
- 不削弱日历样式的 `.ts-root` 隔离；日历若需改动，必须以显示仍然正确为前提。
- 不覆盖用户已经指定的卡片颜色和内容背景。
- 在用户明确批准之前，不升版本、不合并、不发布。
