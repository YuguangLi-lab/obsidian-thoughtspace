# 单文件 Markdown 白板

简体中文 · [主教程](USER-GUIDE.zh-CN.md) · [城市降温研究入门](USER-GUIDE.zh-CN.md#quick-start) · [1.3.35 验证范围](../qa/RELEASE-1.3.35.md)

本页解释 **1.3.35** 的 Markdown 白板创建、原生属性往返、格式另存与保存保护。完整入门用“城市降温研究”依次完成材料收集、脑图和写作；这里保留需要查阅的格式与恢复细节。

Markdown 白板从 1.3.34 开始提供：原生 YAML 属性、普通 Markdown 正文和 ThoughtSpace 布局放在同一个 `.md` 文件。原有 `.thoughtspace` 白板继续使用，不会自动迁移。安装使用同一 Release 的三个运行文件；ZIP 和校验清单需要手动下载核验，见 [安装与更新](USER-GUIDE.zh-CN.md#installation)。

## 创建与打开

1. 从侧栏 **新建 → 新建白板或脑图…**、空间总览新建或同名命令打开统一弹窗。
2. 选择 **白板类型** 和 **文件格式**，填“城市降温研究”或“城市降温问题树”。
3. 点 **创建**。新文件保存在 `ThoughtSpace/白板/`；成功创建并打开后记住本库的类型和格式，已有文件保留原格式。

| 类型 | 旧格式 (.thoughtspace) | Markdown (.md) |
| --- | --- | --- |
| 普通白板 | 自由画布，兼容已有文件 | 自由画布，另有原生属性和正文 |
| 脑图白板 | 当前中心的父子与关联浏览 | 相同脑图操作，另有原生属性和正文 |

初次默认普通旧格式白板。若经常用 Properties，主动选择 Markdown；不需要为旧文件批量迁移。**从模板新建** 同样可选格式，模板的来源卡片仍是独立 Markdown 笔记；成功后只记住所选格式，不改通用新建记住的普通/脑图类型。

命令面板通常显示 `ThoughtSpace Whiteboard:` 前缀，搜索下面的中文名称即可：

| 命令 | 用途 |
| --- | --- |
| 新建白板或脑图… | 在同一弹窗选择类型和格式 |
| 新建旧格式白板 | 明确创建普通 `.thoughtspace` |
| 新建旧格式脑图白板 | 明确创建 `.thoughtspace` 脑图 |
| 新建 Markdown 白板 | 明确创建普通 `.md` 白板 |
| 新建 Markdown 脑图白板 | 明确创建 `.md` 脑图 |
| 以白板打开当前 Markdown | 把当前已声明白板的原生页安全切回白板 |
| 打开白板原生属性与 Markdown | 把当前 Markdown 白板切到正常原生阅读页 |
| 切换白板与原生属性 | 同标签页双向切换，可自行绑定快捷键 |
| 另存为 Markdown 白板 | 从可编辑白板创建独立 `.md` 副本 |
| 另存为旧格式白板 | 创建独立 `.thoughtspace` 副本 |
| 继续上次白板 | 按最近访问打开有效白板，无有效项时打开空间总览 |

明确格式的四个创建命令保持各自语义和已有命令 ID，不被通用新建偏好替换。自由白板新建/转换子白板继承父板格式；独立脑图关系弹窗里的 **新建白板** 仍创建旧格式文件。

插件只注册 `.thoughtspace` 的默认打开方式，**不会全局接管 `.md`**。Obsidian 对 `.md` 的默认打开方式保留，已有白板页可能被复用。若从文件列表或快速切换器打开后进入原生页，文件列表 **以白板打开** 可定位已有白板或另开白板；当前原生页 **返回白板** 使用同页安全交接。ThoughtSpace 白板列表和白板定位链接也可进入白板视图。

普通 Markdown 没有 `thoughtspace: board` 声明时不会列为白板；仅添加声明也不会生成或修复布局。显式打开仍检查整个文件，布局损坏时显示错误并保留原文。

### 创建、取消与偏好的边界

确认前取消不会创建文件。若文件写入已经开始，完成的文件可能留在库中；关闭请求阻止尚未开始的旧目标导航与新建偏好写入。创建并打开后已经启动的偏好保存仍可能完成。

尚未完成任何文件写入的创建失败会保留名称与选择供重试；文件已创建但暂未打开时，按提示从文件列表重开，避免重复创建。偏好保存失败保留已创建文件并给出提示。

模板是多次独立写入，不是原子事务。中途取消或失败可能留下已完成的来源笔记；部分完成后失败会停止自动重试并列出路径，先核对已有文件，再决定是否另开创建请求。

## 用原生 Properties 编辑属性

以“城市降温研究”Markdown 白板为例：

1. 普通白板标题菜单点 **原生属性与 Markdown**；独立脑图点 **脑图菜单 → 原生属性与 Markdown**。
2. 在正常 Obsidian Properties 添加研究标签、状态等属性；需要编辑正文时切换原生编辑模式。
3. 编辑完成后，当前原生页菜单点 **返回白板**，或运行 **以白板打开当前 Markdown**。
4. 还有其他同文件原生页时，先保存并关闭其他页，再从保留页返回。状态里的 **定位原生页** 可帮助寻找。

**切换白板与原生属性** 可自行绑定快捷键，没有默认组合键。旧格式白板没有原生 Properties 入口；可先 [另存为 Markdown](#新旧格式另存)，原文件保留。

插件使用正常 `MarkdownView`，不另造 Properties 编辑器，也不强制修改库的全局属性类型。文本、列表、标签、日期和日期时间遵循 Obsidian 原生规则；用户主动改类型时仍由宿主管理。属性显示方式取决于 Obsidian 设置。

返回前核对当前文件与页面身份、其他同文件原生页及保存状态。编辑模式请求保存；阅读模式核对最新磁盘内容，不用旧缓存回写属性。交接期间暂停布局写入，等原生页卸载再读完整文件。出现新输入、页面切换、更名或保存未完成时，交接取消并保留原生页；保存最新内容后再重试。

无法确认宿主保存状态时，保护继续生效。保留原文件和草稿，不把“页签已经关闭”当作保存与交接都完成。

## 想法与已有笔记

在想法节点菜单选择 **整理成笔记**，可继续生成新笔记，或选择 **保留想法并关联已有笔记**。已有笔记模式保留原想法的正文、标题、节点身份、样式与原关系，仅增加或复用目标文件在此脑图中的引用，并建立双向关联。提交不读取或修改目标正文，正常笔记预览仍可读取正文。

需要给任意支持关系的节点关联已有笔记时，使用节点菜单 **关联已有笔记…**，先在原生选择器选文件，再确认左侧或右侧双向关联。该路径省去来源切换，仍保留确认、取消、文件身份复核及保存失败反馈。

已有笔记模式支持撤销/重做本次白板引用与关系变化；目标笔记正文保持不变。可复用目标笔记的引用节点；同一对节点已有普通关联时，会提示编辑已有连线，不再新增或自动合并重复关联。新建笔记模式的撤销恢复想法引用，已生成的笔记文件仍可能保留，两种模式不能混为同一文件撤销行为。

“树荫”还只是研究想法时，可留在脑图中；已有“树荫观察”笔记时，选择 **保留想法并关联已有笔记**，不必新建同名文件。独立脑图的上下为父子关系，左右为双向关联；深度、中心和四向创建见 [主教程脑图操作](USER-GUIDE.zh-CN.md#mind-maps)。

## 继续最近白板与键盘关系命令

**继续上次白板** 使用最近访问记录，不按文件最近修改时间选择。恢复的是文件内已保存的位置和脑图状态，不是未保存草稿。启动前失效或损坏记录会跳过，没有有效项则打开空间总览；等待打开时的新导航、窗口失焦、卸载或文件身份变化可取消旧请求。

以下四条原生命令均没有默认热键，可在 **Obsidian 设置 → 快捷键** 自行绑定：

| 命令 | 当前中心的关系 |
| --- | --- |
| 脑图：添加父节点 | 新父节点 → 当前中心 |
| 脑图：添加子节点 | 当前中心 → 新子节点 |
| 脑图：添加左侧关联节点 | 左侧节点 ↔ 当前中心 |
| 脑图：添加右侧关联节点 | 当前中心 ↔ 右侧节点 |

命令打开现有创建弹窗，作用于当前活动的独立脑图中心。只读、锁定、正在编辑或创建、IME 组字或文本输入聚焦时不执行；Tab 仍交给焦点和编辑操作。

命令面板显示条目与实际执行是两次检查。关闭面板后恢复到文本输入焦点时，仍受输入保护；先完成并退出编辑。1.3.35 原生探针验证了组字期间保护，但可信 `compositionend` 等待超时，后续正常输入和结束后创建没有执行；不能说完整 OS 输入法开始/提交/结束流程已经原生确认。详见 [输入验收边界](../qa/RELEASE-1.3.35.md#完整进程重开与输入边界)。

## 保存状态的上下文入口

| 状态或提示 | 操作与含义 |
| --- | --- |
| 已保存 | 当前白板布局保存完成；笔记正文与媒体摘录仍需分别确认 |
| 原生 Markdown 已打开 · 白板仅查看 | **定位原生页**；多个页面时先选择，保存其他页，再从保留页返回 |
| 旧原生页保存尚未确认 · 等待保存完成 | 页面已关但仍有缓冲或状态未知，继续等待，不强制解锁 |
| 布局冲突 / 写入暂停 | 只有实际生成且仍存在的草稿才提供 **打开恢复草稿** |
| 恢复草稿不可用 / 保存失败 | 保持当前页面打开，复制可见未保存内容并保留已有恢复文件 |

上下文动作不自动关闭未保存页、解除写保护、覆盖原文件或合并全文。恢复草稿保留本地布局与此前有效文档，不代表已经合并外部最新属性和正文。短操作步骤见 [主教程 FAQ](USER-GUIDE.zh-CN.md#troubleshooting)。

## 同文件的多个视图与同步修改

同一个文件的多个白板视图共享会话和布局撤销历史。只要同一 `.md` 文件还在任意原生 Markdown 页打开，包括阅读模式、Properties 页、另一窗口或尚未加载的恢复标签页，白板就显示 **原生 Markdown 已打开 · 白板仅查看** 并暂停布局写入。这也保护尚未保存的原生输入，检查不会主动加载恢复标签页。

关闭原生标签页，或复用该页打开另一文件后，原生编辑器可能仍在保存旧文件。插件继续记录原页对应的文件身份，直到当前保存及宿主排队的后续保存（`saving` 和 `saveAgain`）都完成，才解除该文件的布局写入保护并重试后台引用更名。它不会读取或保存已经关闭页面的编辑缓存；无法确认这些保存状态时也不会提前解锁。因此，页签消失后短暂保留仅查看状态是正常的保护行为。

在同一应用内重载插件时，插件通过工作区所属窗口上的弱引用继续识别此前已经观察的原生文件与编辑器，旧保存尚未结束时仍保留保护。卸载会释放旧计时器、监听器和强引用；桥中不保存正文或布局。它不提供跨进程的未保存草稿存储，也不保证完全停用期间从未观察的新编辑器受到该保护。

需要继续布局时，请保存并关闭其他同文件原生页，再从当前原生页显式返回白板。不会为了恢复可编辑状态自动关闭其他页面或丢弃原生草稿。

布局保存通过 Obsidian 的文件处理接口重新读取当前原文，只替换插件拥有的布局区：

- 区外的未知 YAML 属性、Markdown 正文、注释和其他文本按当前磁盘内容保留，不会被插件重新序列化。
- 仅区外内容变化时，可继续保存布局；读取这些变化不会清空已有布局撤销历史。
- 布局区也被其他窗口或同步工具修改时，不覆盖磁盘中的另一份布局。当前白板暂停写入，并尝试在原目录创建同格式的 **恢复草稿** 文件。
- 恢复草稿包含本地布局和会话中最后验证过的文档内容；发生布局冲突后，应对照原文件与草稿处理两边的属性、正文和布局。它不是自动合并全部冲突后的结果。
- 恢复文件创建也失败时，保持当前页面打开，复制可见未保存内容并保留已有恢复文件。通用导出可能受写保护限制，或读取磁盘旧内容，不保证包含未落盘的本地布局；不要仅因生成导出文件就清除当前会话。

原生 Properties 自身可能整理 YAML 的排版或注释，这是宿主编辑行为。插件的“区外原文保留”约束适用于布局写入，不承诺原生属性编辑也逐字保留 YAML 排版。

## 原生页打开时更名来源

在同文件原生 Markdown 页打开期间，关联笔记、PDF、材料目录或白板改名后，插件暂缓修正 Markdown 白板布局里的引用路径，保留原关系。它会尝试把等待记录保存到当前库的插件设置数据中；记录只包含操作标识和更名时的库内路径快照，不缓存笔记正文、YAML 属性或白板布局内容，也不会为了更新引用回写尚未保存的原生页面。

等待记录成功写入后，提示会明确说明 **来源已改名**、布局引用将在保存并关闭原生 Markdown 页后更新，以及 **等待记录已保存**。这表示修正已经排队，尚不表示布局引用已经更新。

保存并关闭同文件原生页，或在当前原生页运行 **以白板打开当前 Markdown** 后，插件等原页的全部保存完成，再按原顺序重试这些更名。重试读取最新白板文件，只修正布局中的引用，继续保留最新原生属性和正文。布局修正写入完成后，才移除对应等待记录；插件重开时也会读取已保存的记录并尝试重放。仍有原生页打开或旧页保存未完成时继续等待，目标白板缺失时也不会转而修改其他文件。

等待记录保存失败会明确提示 **来源改名等待记录保存失败**，说明 **当前内存可重试，但重启恢复尚未确认**。不能将其视为“已保存”或“引用已更新”；解决保存问题后，可在当前会话重试同一记录，只有可靠写入设置后才有持久化保障。后续布局写入或移除完成记录失败时，等待记录保留，错误会提示；应先解决保存问题再重试。已有等待记录或正在重放时发生下一次来源更名，新更名同样追加到顺序日志；先前失败的 A→B 与后续 B→C 会依次重试，避免跳过尚未应用的路径变化。记录达到容量上限时，也会明确报错，不淘汰此前未完成的更名。

等待记录仅接受规范的库内相对路径；这一约束只用于新增的等待记录，不是对既有 `.thoughtspace` 文件格式重新设定规则。白板能否打开仍须验证原生属性声明与完整布局数据。

## 新旧格式另存

普通白板标题菜单可选 **另存为 Markdown 白板 / 另存为旧格式白板**，或运行同名命令，输入副本名称后确认；确认前取消不创建副本。脑图需要另存时可运行对应命令。

另存先完成当前会话已有的布局保存，再从最新有效文件创建副本。操作不会转换或删除原文件，也不会把已有链接批量改向新文件。新副本使用新的 `spaceId`，以区分布局快照等白板身份；节点 ID、连线和节点引用路径保留。

| 来源 → 副本 | 复制的内容 |
| --- | --- |
| `.thoughtspace` → `.md` | 白板数据进入新的 Markdown 布局区，并添加原生属性声明和标题 |
| `.md` → `.md` | 属性、正文和布局区外文本保留，白板使用新的 `spaceId` |
| `.md` → `.thoughtspace` | 复制白板数据；YAML 属性和 Markdown 正文仍在原 `.md` 中，旧格式副本不包含这些内容 |
| `.thoughtspace` → `.thoughtspace` | 创建独立白板副本，原文件继续使用 |

笔记、图片、音视频、PDF 与其他白板的引用仍指向原有库内路径，另存不会复制这些材料。跨白板引用保留原目标；指向原白板自身的路径也继续指向原文件。若希望副本建立新的关联，请在副本中明确修改。

暂停写入或存在同文件原生页时，需先完成保存或处理冲突，才能另存。格式读取失败时不创建半成品副本。

## 文件格式

下面是一个空白板的完整示例。用户属性放在顶部 YAML 中，正文可写在布局区前后。布局标记必须各出现一次，区域内必须有一个完整的 `json` 代码块。

````markdown
---
thoughtspace: board
status: reading
tags:
  - research/urban-cooling
---

# 城市降温研究

研究问题：街道树荫如何影响行人感受到的热？

这里记录研究摘要与普通 Markdown 链接。

<!-- thoughtspace-board-layout:start -->
```json
{
  "format": "thoughtspace-board",
  "version": 1,
  "board": {
    "version": 1,
    "nodes": [],
    "edges": [],
    "viewport": { "x": 60, "y": 60, "zoom": 1 }
  }
}
```
<!-- thoughtspace-board-layout:end -->

布局区之后也可以继续写正文。
````

`thoughtspace` 必须是文本值 `board`。JSON 外层的 `version: 1` 是 Markdown 文件布局封装版本，和内部白板数据的版本分别检查。布局标记、代码块及 JSON 由插件管理；日常编辑属性与正文时，请保留这一整段。

停用插件后，这仍是一份 Markdown 文件：Obsidian 可显示原生属性、标题、正文和 JSON 代码块。可视化白板操作需要插件，原文件不依赖搜索索引才能保存布局。

## 损坏文件与恢复

以下情况会拒绝打开或保存布局，不覆盖原文件：无效 YAML、缺失或重复布局标记、损坏代码块、无效 JSON、未知封装版本，以及无效白板数据。出错页面提供 **打开 Markdown 修复**，转到正常原生 Markdown 页查看原文。

修复前可以先复制文件留档；修正原文后保存，再运行 **以白板打开当前 Markdown**。也可以保留损坏文件，另开已有备份或恢复草稿。插件不会静默删掉重复布局区、降级未知版本或重建为空白板。

## 1.3.34 基线验证与恢复边界

1.3.34 使用 Obsidian 1.14.4 的独立自制库与配置完成真实鼠标键盘、取消、撤销重做、关闭后首存及后续保存、插件重载、完整应用重开和强制退出对照。以下结果属于 1.3.34 基线验证。原生检查包含环境和错误断言，不能把断言数当作独立业务功能数。详细方法、构建哈希、同样本性能与明确限制见 [1.3.34 验证说明](../qa/RELEASE-1.3.34.md)；新增便利性操作的验证见 [1.3.35 验证说明](../qa/RELEASE-1.3.35.md)。

已落盘的最新版本在本轮强制终止后恢复。尚未保存的原生输入在暂停实际保存和自然保存前窗口中丢失，完全不加载候选的宿主对照结果相同。实际 File recovery 界面仅找到保存基线快照，全文中没有最新未保存输入；不能将快照存在说成最新草稿可恢复。插件没有为任意原生正文另建持久备份，弱身份桥只在同一运行应用内保留已观察编辑器的保存保护。

两个原生编辑器持有不同整篇副本时，稍后的宿主保存可能覆盖较早草稿或外部文件修改。本轮双窗口的基线是同一已加载候选应用内的普通 Markdown 对照；它与完全不加载候选的三组强制退出对照分别报告。候选阻止已知原生保存期间的布局提交，但不合并宿主整篇草稿。

外部写入测试使用专用库的本地文件系统，不是真实 Obsidian Sync 账号或网络验收。性能样本为 1000 个总节点、6 个实际挂载节点和 5 条渲染连线，不表示同时渲染 1000 节点。没有清除 OS 缓存、强制 GC 或验证物理 fsync/断电完整性，也没有通用提速或无内存泄漏结论。全部宿主版本、第三方主题与插件组合未覆盖。
